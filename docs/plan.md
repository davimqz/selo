## 2. Program design

### 2.0 Settlement model

Selo models a **usance letter of credit: payment against documents**, not against buyer confirmation.

- Once the buyer funds the escrow, the buyer **cannot block payment**. Payout depends only on
  attestations by allowlisted attesters and on the calendar.
- Default `required_milestones = INSPECTED | SHIPPED | EUDR_COMPLIANT`. `DELIVERED` is optional; if a
  deal requires it, a destination surveyor in the allowlist attests it (the buyer may also attest it,
  but is never the only path).
- `expires_at` = latest shipment date. `refund()` is only possible if `SHIPPED` was **not** attested by
  `expires_at`. After `SHIPPED` there is no on-chain refund; disputes are off-chain, as with a real L/C.
- `payment_due_at` = usance maturity. `settle()` requires `required ⊆ attested` **and**
  `now >= payment_due_at`. A financier who advanced is repaid first.
- Rule at `create_deal`: `now < expires_at <= payment_due_at`. The demo seed uses a short
  `payment_due_at` (e.g. +60 s) so the whole flow fits in the video.

### 2.1 Constants

Milestones are bit flags so a deal stores "required" and "attested" sets in one byte:

| Milestone | Bit |
| --- | --- |
| `INSPECTED` | `1 << 0` |
| `SHIPPED` | `1 << 1` |
| `EUDR_COMPLIANT` | `1 << 2` |
| `DELIVERED` | `1 << 3` |

`required_milestones` must include `SHIPPED` (refund and advance hinge on it) and use known bits only.

Document types: `BILL_OF_LADING = 0`, `COMMERCIAL_INVOICE = 1`, `CPR = 2` (Cédula de Produto Rural).

`BPS_DENOMINATOR = 10_000`, `MAX_ATTESTERS = 4`.

### 2.2 Accounts

#### `Deal` — PDA `["deal", seller, deal_id.to_le_bytes()]`

`deal_id: u64` is chosen by the seller (the client uses a timestamp/nonce), so one seller can run many deals.

| Field | Type | Notes |
| --- | --- | --- |
| `deal_id` | `u64` | seed |
| `seller` | `Pubkey` | creator, receives advance and balance |
| `buyer` | `Pubkey` | funds escrow; may attest `DELIVERED` |
| `usdc_mint` | `Pubkey` | every token account is checked against it |
| `amount` | `u64` | escrow amount (base units) |
| `max_advance_bps` | `u16` | cap for the financier advance |
| `advance_fee_bps` | `u16` | financier fee on the advanced principal |
| `required_milestones` | `u8` | must be ⊆ `attested_milestones` to settle; always includes `SHIPPED` |
| `attested_milestones` | `u8` | updated by `attest_milestone` |
| `documents` | `u8` | bitmask of registered doc types |
| `bill_of_lading` | `Pubkey` | the B/L `DocumentRecord` (default = none) |
| `attester_mode` | `u8` | `0 = Allowlist`, `1 = Sas` (Phase 2) |
| `attesters` | `[AttesterEntry; 4]` | `{ key: Pubkey, milestones: u8 }`; unused slots = default key |
| `sas_credential` | `Pubkey` | Phase 2, default until then (reserved now to avoid realloc) |
| `sas_schema` | `Pubkey` | Phase 2, idem |
| `financier` | `Pubkey` | set by `advance` (default = none) |
| `advanced_amount` | `u64` | principal paid to seller |
| `repay_amount` | `u64` | principal + fee, paid first on `settle` |
| `status` | `DealStatus` | `Created → Funded → Advanced → Settled`; `Funded → Refunded`; `Created → Cancelled` (terminal, account kept) |
| `created_at` | `i64` | |
| `expires_at` | `i64` | latest shipment date (deadline for `SHIPPED`) |
| `payment_due_at` | `i64` | maturity; `settle` allowed from here on |
| `bump`, `vault_bump` | `u8` | canonical bumps stored at init |

Invariant enforced at `create_deal`: `max_advance_bps * (10_000 + advance_fee_bps) <= 10_000²`,
so `repay_amount <= amount` always and settlement can never underflow the vault.

#### `Vault` — SPL token account PDA `["vault", deal]`

`token::mint = deal.usdc_mint`, `token::authority = deal` (the Deal PDA signs transfers). Created in
`fund_escrow` (payer = buyer), closed on `settle`/`refund` with rent returned to the buyer.

#### `DocumentRecord` — PDA `["doc", doc_hash]`

| Field | Type |
| --- | --- |
| `doc_hash` | `[u8; 32]` |
| `doc_type` | `u8` |
| `deal` | `Pubkey` |
| `registered_by` | `Pubkey` |
| `registered_at` | `i64` |
| `bump` | `u8` |

`doc_hash` is computed client-side from canonicalized fields (spec in
[`architecture.md`](architecture.md#document-hash-canonicalization), implemented once in `sdk/` and
shared by tests, scripts and app). No per-user salt in v1. Only the hash goes on-chain.
**Never closed**: the existence of the PDA *is* the anti-double-pledge lock.

The instruction takes the PDA as an unchecked account with a `seeds` constraint and, if it already
holds program-owned data, fails with `DocumentAlreadyRegistered` (a readable error instead of the
System Program's "already in use"). Creation uses transfer + allocate + assign, so a griefer who
pre-funds the PDA with lamports cannot block registration.

The program cannot check canonicalization, so the **financier's client recomputes the canonical hash
from the B/L it is shown and passes that record to `advance`**; `advance` checks that the record is
this deal's B/L. A seller who registers a non-canonical hash cannot get that deal financed.

#### `MilestoneRecord` — PDA `["milestone", deal, [milestone_bit]]`

| Field | Type | Notes |
| --- | --- | --- |
| `deal` | `Pubkey` | |
| `milestone` | `u8` | single bit |
| `attester` | `Pubkey` | who signed |
| `evidence_hash` | `[u8; 32]` | hash of inspection report / photo / EUDR DDS reference |
| `sas_attestation` | `Pubkey` | Phase 2 (default in allowlist mode) |
| `attested_at` | `i64` | |
| `bump` | `u8` | |

Created with `init`: each milestone can be attested exactly once per deal.

### 2.3 Instructions

Every instruction: signer checks, `has_one`/constraints, canonical bumps, mint + owner checks on token
accounts, `checked_*` math, explicit status transitions.

| # | Instruction | Signer | Preconditions | Effects |
| --- | --- | --- | --- | --- |
| 1 | `create_deal(deal_id, buyer, amount, max_advance_bps, advance_fee_bps, required_milestones, attesters, expires_at, payment_due_at)` | seller | `amount > 0`; bps invariant; `now < expires_at <= payment_due_at`; `SHIPPED ∈ required`, known bits only; 1–4 attesters, non-default, no duplicates, each with a non-empty known mask; buyer ≠ seller | init `Deal` (`Created`) |
| 2 | `fund_escrow()` | buyer | `deal.buyer == signer`; status `Created`; `now <= expires_at`; buyer token account mint/owner | init vault; transfer `amount` → vault; status `Funded` |
| 3 | `register_document(doc_hash, doc_type)` | seller | `deal.seller == signer`; status **`Funded` only**; doc type not yet on this deal | create `DocumentRecord`; set bit; store B/L; **`DocumentAlreadyRegistered` if the hash exists on any deal** |
| 4 | `attest_milestone(milestone, evidence_hash)` | attester | status `Funded`/`Advanced`; single bit ∈ `required`; signer authorized (allowlist entry with that bit, or buyer for `DELIVERED`; SAS in Phase 2); `SHIPPED` only while `now <= expires_at`; after `expires_at`, other milestones only if `SHIPPED` is attested | init `MilestoneRecord`; set bit in `attested_milestones` |
| 5 | `advance(amount)` + B/L `DocumentRecord` | financier | status `Funded`; record is this deal's B/L; `SHIPPED` attested; `0 < amount <= deal.amount * max_advance_bps / 10_000`; financier ≠ seller/buyer; `now < payment_due_at` | transfer financier token acct → seller token acct; record financier, principal, repay; status `Advanced` |
| 6 | `settle()` | anyone (crank) | status `Funded`/`Advanced`; `required ⊆ attested`; `now >= payment_due_at` | vault → financier `repay_amount` (if advanced), rest → seller; close vault; status `Settled` |
| 7 | `refund()` | anyone (crank) | status `Funded`; `now > expires_at`; **`SHIPPED` not attested** | vault → buyer; close vault; status `Refunded` |
| 8 | `cancel()` | seller or buyer | status `Created` (nothing funded, no documents) | status `Cancelled` (account kept: the address can never be re-created with other terms — audit F-1); `DealCancelled` |

`Advanced` implies `SHIPPED` (advance requires it), so `refund` never applies to `Advanced` deals.

**Known limitation (documented, not solved in the MVP):** if a required milestone after `SHIPPED` is
never attested (the attester disappears), funds stay locked. Mitigation in the roadmap: arbiter,
dispute window, attester replacement.

### 2.4 Errors (`SeloError`)

`InvalidAmount`, `InvalidBps`, `InvalidSchedule`, `InvalidMilestone`, `ShippedNotRequired`,
`MilestoneNotRequired`, `InvalidAttesters`, `InvalidParties`, `UnauthorizedAttester`,
`ShipmentDeadlinePassed`, `NotShipped`, `InvalidDocumentType`, `DocumentAlreadyRegistered`,
`DocumentTypeAlreadyOnDeal`, `BillOfLadingMismatch`, `AdvanceExceedsLimit`, `FinancierIsParty`,
`MissingMilestones`, `PaymentNotDue`, `PaymentDue`, `DealExpired`, `DealNotExpired`,
`AlreadyShipped`, `InvalidStatus`, `MathOverflow`.
Phase 2: `InvalidSasAttestation`, `SasAttestationExpired`.

Mint/owner mismatches on token accounts surface as Anchor constraint errors. Every error maps to a
user-facing message in the app (Phase 3).

### 2.5 Events (`emit!`)

`DealCreated`, `EscrowFunded`, `DocumentRegistered`, `MilestoneAttested`, `AdvanceFunded`,
`DealSettled { to_financier, to_seller }`, `DealRefunded`, `DealCancelled`. All carry `deal` and a
timestamp; the `/deal/[id]` timeline is built from these plus account state.

## 3. Tests (Phase 1)

LiteSVM, in-process, with clock control. The `sdk/` doc-hash vectors run in the same suite.

| Area | Happy path | Failure cases |
| --- | --- | --- |
| doc hash | `"MAEU-123 456"` ≡ `"maeu123456"`; CNPJ `12.345.678/0001-90` ≡ `12345678000190`; pinned known vector | invalid SCAC / CNPJ; empty number; different types give different hashes |
| `create_deal` | fields stored, event emitted | amount 0; bps invariant broken; `expires_at <= now`; `expires_at > payment_due_at`; `SHIPPED` not required; unknown bit; no / duplicate attesters; attester with empty mask; buyer == seller |
| `fund_escrow` | vault holds `amount`, status `Funded` | wrong buyer; token account of the wrong mint; double fund; after `expires_at` |
| `register_document` | record created, B/L stored | before funding (`Created`); non-seller; **same hash on the same deal**; **same hash on a second deal (demo step 2)**; same type twice; invalid type |
| `attest_milestone` | allowlisted attester; destination surveyor attests `DELIVERED`; buyer attests `DELIVERED` | unauthorized signer; attester without that bit; buyer attesting `SHIPPED`; milestone not required; multi-bit value; double attest; `SHIPPED` after `expires_at`; milestone after `expires_at` without `SHIPPED` |
| `advance` | seller receives advance, repay stored | no B/L; B/L of another deal; non-B/L document; no `SHIPPED`; above limit; zero; second advance; financier = seller/buyer; wrong mint; seller token account owned by someone else |
| `settle` | financier repaid first, seller gets the rest; without advance everything to seller; vault closed | **before `payment_due_at`**; missing required milestone; double settle; vault of another deal; payout to a wrong token account |
| `refund` | buyer refunded if not shipped by `expires_at` | before `expires_at`; **buyer cannot refund after `SHIPPED`, even past `expires_at`**; after settle |
| `cancel` | seller/buyer cancels an unfunded deal | third party; after funding |

## 4. Decisions (approved 2026-09-27)

1. Document hash: domain separator `selo:doc:v1` + canonicalized fields, no per-user salt. Spec in
   `architecture.md`.
2. L/C model: payment against documents; the buyer cannot block payment; refund only if not shipped
   by `expires_at`.
3. Usance: `payment_due_at`, with `now < expires_at <= payment_due_at`.
4. One financier, one advance per deal; fee and cap set by the seller at `create_deal`.
5. `register_document` only in `Funded`.
6. `settle` and `refund` are permissionless cranks.
7. `emit!` (log events).

## 5. Demo mapping

1. Exporter creates the deal (buyer funds) and registers the B/L.
2. Exporter tries to register the **same B/L on a second deal** with another financier →
   `DocumentAlreadyRegistered`.
3. Inspector attests `SHIPPED` from a phone → financier advances → USDC lands in the exporter's wallet.
4. Destination surveyor attests; once `payment_due_at` is reached, `settle` pays the financier, then
   the exporter.
